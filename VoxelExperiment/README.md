# VoxelExperiment

Компоненты для вычислительного эксперимента по воксельным представлениям: плотная сетка, блочная сетка, SVO и SVDAG. Структуры строятся на CPU, лучи трассируются в пиксельном шейдере на GPU, результаты пишутся в CSV.

## Запуск

```
GPU-Renderer.exe --voxel-experiment
GPU-Renderer.exe --voxel-experiment --voxel-resolutions=256,512,1024 --voxel-model="C:\models\bunny_512.binvox"
```

Без флага `--voxel-experiment` приложение работает как раньше (кубы `Box`).

| Опция | По умолчанию | Назначение |
|---|---|---|
| `--voxel-scenes=sphere,terrain` | обе | процедурные сцены (`none` — только модели) |
| `--voxel-resolutions=256,512,1024` | 256,512,1024 | разрешения N процедурных сцен (степени двойки ≥ 16) |
| `--voxel-model=path.binvox` | — | модель, можно повторять; N берётся из файла |
| `--voxel-representations=dense,block,svo,svdag` | все | сравниваемые представления |
| `--voxel-views=3` | 3 | число фиксированных ракурсов |
| `--voxel-warmup=30` | 30 | кадров прогрева на ракурс |
| `--voxel-series=10` / `--voxel-frames=20` | 10 / 20 | серии и кадры в серии |
| `--voxel-cpu-stride=4` | 4 | шаг выборки пикселей для CPU-подсчёта шагов на луч |
| `--voxel-report=path.csv` | voxel_experiment.csv | файл результатов |
| `--voxel-view-only` | — | без замеров, сразу просмотр сцен (CSV не создаётся) |

Для отладки в Visual Studio аргументы задаются в «Свойства проекта → Отладка → Аргументы команды». Шейдеры `VoxelTraceVS.cso` и `VoxelTracePS.cso` компилируются в каталог проекта (как и существующие), поэтому рабочим каталогом должен быть он.

## Что измеряется

Для каждой сцены, N, представления и ракурса в CSV записывается строка:

- `boundary_voxels` — число граничных вокселей (оболочка по 6-соседству);
- `generation_ms`, `build_ms` — время генерации сцены и построения структуры на CPU;
- `memory_bytes` — точный объём буфера, переданного на GPU;
- `cpu_rays`, `cpu_mean_steps`, `hit_rate` — число лучей, среднее число шагов обхода на луч и доля попаданий. Считаются на CPU копией шейдерного алгоритма (`RayTraversal.cpp`) для того же кадра, поэтому от аппаратуры не зависят. По умолчанию берётся каждый 4-й пиксель по обеим осям: при 1920×1080 среднее отличается от полного обхода не больше чем на 0,2 %, а лучей в 16 раз меньше;
- `gpu_ms_mean`, `gpu_ms_std` — время кадра на GPU (timestamp-запросы D3D11): среднее и выборочное СКО по сериям, где каждая серия — среднее по `frames` кадрам;
- `mrays_per_s` — W·H / время кадра;
- `gpu_status` — `ok`, `skipped: ...` (плотная сетка при N > 1024: индекс в шейдере 32-битный) или `failed: ...` (например, буфер превысил предел размера ресурса D3D11 — это тоже результат).

CSV разделён `;`, поэтому открывается в Excel с русской локалью без настройки. Показатель роста памяти α (M ∝ N^α) считается по столбцу `memory_bytes`. В коде для этого есть `FitPowerLawExponent`.

## Просмотр сцен

После прогона (или сразу, с `--voxel-view-only`) открывается просмотр. Текущая сцена, представление и объём памяти показываются в заголовке окна.

| Клавиша | Действие |
|---|---|
| ← / → | предыдущая / следующая сцена |
| ↑ / ↓ | следующее / предыдущее представление |
| 1 / 2 / 3 | ракурс эксперимента 0 / 1 / 2 (камера встаёт в него и останавливается) |
| P | сохранить кадр в BMP в текущий каталог (без рамки окна) |
| H | тепловая карта числа шагов на луч (иллюстрация к оценке сложности обхода; шкала логарифмическая, от 1 до 3N + 1 шагов, общая для всех представлений: синий — мало шагов, жёлтый — много) |
| Пробел | пауза вращения камеры |

Сцены, сгенерированные во время замеров, хранятся в памяти (до 16 млн граничных вокселей на сцену, это примерно 128 МБ). Остальные генерируются заново при переключении. Структура перестраивается при каждом переключении, и окно на это время не отвечает. Во время замеров клавиши игнорируются, чтобы не влиять на результаты.

## Модели

Вокселизация — [cuda_voxelizer](https://github.com/Forceflow/cuda_voxelizer), формат binvox:

```
cuda_voxelizer -f model.obj -s 512 -o binvox
```

Размер дополняется до степени двойки, затем выделяется оболочка по 6-соседству. Поэтому подходит и поверхностная вокселизация (по умолчанию), и сплошная (`-solid`). Поверхностная вокселизация даёт более толстую оболочку: c ≈ 1,5 против ≈ 0,83 у 6-оболочки. Разрешение задаётся при вокселизации, отдельный файл на каждое N. Порядок осей binvox: быстрее всего меняется y, затем z, затем x. Если модель «лежит на боку», переставьте оси в `LoadBinvox`.

## Рисунки статьи

**Рисунок 1** (объём, число шагов и время кадра от N) строится по CSV прогонов:

```
python Analysis/plot_scaling.py review_main.csv --time review_time.csv --preview
```

Получится `figure1.tif` (17 × 5,6 см, 300 dpi): три панели в логарифмических осях, сфера – сплошные линии, ландшафт – штриховые; на панели времени – сфера, отрезки – разброс по ракурсам. `--time-scene terrain` – время для ландшафта.

**Рисунок 2** (тепловые карты числа шагов):


1. `GPU-Renderer.exe --voxel-experiment --voxel-scenes=terrain --voxel-resolutions=1024 --voxel-representations=svo,dense,block --voxel-view-only`
2. Нажать `1` (ракурс эксперимента 0, камера остановится).
3. Сделать четыре снимка клавишей `P`:
   - `svo` без тепловой карты — панель а);
   - `H` (включить тепловую карту), затем `svo`, `dense` (`↑`/`↓`), `block` — панели г), б), в).

   Файлы появятся рядом с exe: `capture_terrain_N1024_svo_shade_view0.bmp`, `capture_terrain_N1024_dense_steps_view0.bmp` и т. д.; результат сохранения виден в заголовке окна.
4. Собрать рисунок (нужны `pip install matplotlib pillow`):

   ```
   python Analysis/make_figure.py --scene terrain --resolution 1024 --view 0 --crop 0.2,0,0.85,1 --preview
   ```

   Получится `figure2.tif` (17 см, 300 dpi, LZW) и `figure2.png` для просмотра: четыре панели в ряд, подписи а)–г), шкала цветов той же палитры, что в шейдере (логарифмическая, от 1 до 3N + 1 шагов). `--crop` обрезает пустые поля кадра по бокам (доли ширины и высоты), `--layout grid` — раскладка 2 × 2 шириной 12 см, `--font`, `--font-size` — шрифт подписей.

## Структура

Ядро (без DirectX, собирается на любой платформе):

| Файл | Содержимое |
|---|---|
| `Morton.hpp` | кодирование Мортона |
| `VoxelGrid.*` | `IVoxelGrid`, `DenseGrid`, `BlockGrid`, `SparseVoxelOctree`, `SparseVoxelDag`, `BuildGrid` |
| `SceneGenerators.*` | сфера, ландшафт с пещерами (многопоточно), чтение и запись binvox, `SceneCase` и `LoadSceneCase` |
| `RayTraversal.*` | камера, CPU-копия обхода лучей (DDA и иерархический) |
| `ExperimentReport.*` | CSV, среднее, СКО, МНК для степенного закона |
| `ExperimentConfig.*` | параметры и разбор командной строки |
| `FrameCapture.*`, `ImageFile.*` | снимок заднего буфера в 24-битный BMP (клавиша P) |
| `Analysis/plot_scaling.py` | рисунок 1: объём, шаги и время от N по CSV |
| `Analysis/make_figure.py` | сборка рисунка 2 из снимков: панели, подписи, шкала цветов, TIF 300 dpi |

Компоненты DirectX 11 (в архитектуре проекта):

| Файл | Содержимое |
|---|---|
| `StructuredBuffer.hpp` | `bindable::StructuredBuffer` — `StructuredBuffer<uint>` в регистре t* |
| `GpuTimer.*` | `profiling::GpuTimer` — timestamp-запросы (в `Graphics` добавлен `friend`) |
| `VoxelVolume.*` | `drawable::VoxelVolume : DrawableBase` — полноэкранный прямоугольник и константы трассировки |
| `VoxelTraceVS.hlsl`, `VoxelTracePS.hlsl` | вершинный и пиксельный шейдеры (SM 5.0) |
| `ExperimentRunner.*` | автомат эксперимента, по кадру за вызов |
| `SceneViewer.*` | просмотр сцен с переключением с клавиатуры |
| `ExperimentApplication.*` | окно и цикл сообщений, как у `Application` |

Изменения вне каталога: `Graphics.hpp` (friend `profiling::GpuTimer`), `Window.hpp/.cpp` (`SetTitle`), `WinMain.cpp` (выбор приложения по флагу), `GPU-Renderer.vcxproj` и `.filters` (новые файлы, шейдеры SM 5.0).

Для выноса в отдельный проект ядро переносится как есть. Компонентам DirectX нужны `Bindable`, `Drawable`/`DrawableBase`, `Graphics`, шейдерные и буферные `Bindable` основного проекта: они подключаются по относительным путям `../`, их нужно заменить на путь к общей библиотеке.

## Тесты ядра

```
g++ -O2 -std=c++20 -pthread VoxelExperiment/Tests/VoxelCoreTests.cpp VoxelExperiment/VoxelGrid.cpp \
    VoxelExperiment/SceneGenerators.cpp VoxelExperiment/RayTraversal.cpp \
    VoxelExperiment/ExperimentReport.cpp VoxelExperiment/ExperimentConfig.cpp \
    VoxelExperiment/ImageFile.cpp -o voxel_core_tests
```

В MSVC: `cl /std:c++20 /O2 /EHsc /utf-8` с теми же файлами. Тесты проверяют согласованность запросов и лучей всех представлений, отсутствие зацикливания обхода (число шагов не превышает оценку худшего случая), формулу числа граничных вокселей, границу 255 узлов SVDAG, выборку пикселей, binvox, статистику и разбор командной строки.

## Ограничения

- Время кадра измеряется с блокирующим ожиданием результатов запросов, без конвейеризации кадров. Это замер одной отрисовки, а не FPS приложения.
- Подготовка структуры выполняется в потоке окна, поэтому окно на это время не отвечает (при N = 1024 — до десятков секунд, в основном ландшафт и CPU-обход плотной сетки).
